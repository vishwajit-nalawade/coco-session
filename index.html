01 — Overview

What is Cortex Code Desktop?

A desktop application connected directly to your Snowflake account. Ask questions and give instructions in plain English. CoCo writes the SQL, runs it, and shows you the results.

Q

Query and Explore

  • Ask data questions in plain English
  • CoCo writes and executes the SQL
  • Inline charts and visualizations
  • Search tables, views, and schemas by description
B

Build and Debug

  • Write, fix, and explain SQL or Python
  • Generate Snowpark code
  • Create tables, views, dynamic tables, tasks
  • Debug pipeline failures end to end
M

Manage and Govern

  • Manage grants and role assignments
  • Investigate table and column lineage
  • Analyze cost and credit usage
  • Monitor data quality with DMFs
CoCo respects your existing Snowflake RBAC. It operates under your user and your active role — no elevated access, no bypassing grants.
02 — Core Concepts

How CoCo Works

Four building blocks make CoCo useful for your specific work from day one.

Skills

80+ built-in specialized workflows. Dynamic tables, data quality, cost analysis, governance, alerts, migrations, and more. CoCo loads the right skill automatically based on your question. Teams can also build and share custom skills.

Sessions

Every conversation is saved automatically. Resume multi-day work, rewind to earlier points, or branch off to try a different approach. Close the app and pick up where you left off tomorrow.

Memory

CoCo remembers context you tell it to keep — database names, team conventions, project details. This persists across sessions so you never repeat yourself.

Agents

For complex, multi-step tasks, CoCo launches background agents that work autonomously and report back. You can keep chatting while they work.

03 — Prompt Strategies

Getting the Best Out of CoCo

The quality of your output depends on the quality of your input. Be specific, be contextual.

Weak
"Show me data"
Strong
"Show me row count and last refresh time for all tables in ANALYTICS_DB.CORE_SCHEMA"
Weak
"Fix this"
Strong
"This SP fails with 'invalid identifier' on line 42 — here's the code: ..."
Weak
"Create a pipeline"
Strong
"Create a DT joining FACT_ORDERS with DIM_CUSTOMERS, refreshing every 30 min"

Power-User Tips

Invoke skills directly

Ask about "dynamic tables," "data quality," or "cost intelligence" and CoCo loads the specialized workflow automatically.

Iterate in the same session

After a query result: "Add a filter for active devices" → "Chart that by month" → "Export as a CREATE VIEW."

Use CoCo for investigation

"What depends on this table?" (lineage) · "Why is this DT failing?" (diagnostics) · "Who has access?" (governance)

Offload tedious work

Test cases from work items, data comparison before and after reload, bulk ALTER statements, GRANT across roles.

Schedule recurring work

Use /automation to schedule CoCo runs as Snowflake tasks — recurring reports, freshness checks, cost digests.

04 — Guidelines

Best Practices

Follow these guidelines for safe, effective use of CoCo across the team.

1

Review before executing

Always review generated DDL/DML before confirming, especially on production schemas. Say "just compile, don't execute" when in doubt.

2

Set your role deliberately

Run USE ROLE at the start of a session if the default role isn't what you need for the task at hand.

3

Break complex asks into steps

Work incrementally: show schema, then write join, then wrap as DT. Better results than one massive prompt.

4

Validate outputs

CoCo is an assistant, not a deployment pipeline. Test in dev/sandbox first. Use your normal standard PR flow for production.

5

Use memory for recurring context

Tell CoCo to remember database names, conventions, and project details so you don't repeat yourself every session.

6

Never paste secrets

No connection strings, passwords, or tokens in the chat. Use Snowflake's secret management or environment variables.

05 — Live Demos

Use Cases

Real-world examples from our team's daily workflow.

Scenario: A dynamic table shows UPSTREAM_FAILED and is not refreshing.
1
> Show me the refresh history for dynamic table ANALYTICS_DB.CORE_SCHEMA.DT_ORDER_SUMMARY
2
> Why did the last refresh fail? Show me the error details.
3
> What are the upstream dependencies of this dynamic table?
4
> Check if any of the upstream base tables were altered recently
Replaces manually querying multiple INFORMATION_SCHEMA views and tracing upstream objects one by one.
Scenario: A new work item describes SP_UPSERT_CUSTOMER_DATA. You need structured test cases.
> "Generate ETL test cases for this requirement: As a data engineer, I need a stored procedure SP_UPSERT_CUSTOMER_DATA that reads from STG_CUSTOMER_FEED, validates customer_id is not null, checks for duplicates, and upserts into DIM_CUSTOMER on customer_id as merge key. It should log row counts to an audit table."

CoCo generates a structured Excel workbook:

Positive Path

Valid data flows through correctly

Negative Path

Null customer_id rejected, duplicates handled

Boundary Tests

Empty source table, large batch sizes

Audit Validation

Row counts logged correctly

This uses a custom skill built by our team. Any team member can create and share skills for repetitive workflows.
